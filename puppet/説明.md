# 立ち絵1枚から作る「ライブ2D風パペット」

正面の立ち絵1枚から、ライブ2Dのように**まばたき・視線・顔の向き・口パク・呼吸・髪揺れ**で動くキャラクター(パペット)を作り、
ウェブページやアプリに組み込めるようにしたものです。

本家のライブ2D(Cubism Editor)は使っていません。画像の分解・リグ(動かす仕組み)の生成・表示エンジンまで、すべてこのフォルダの中で完結します。

## できること

| 動き | 内容 |
|---|---|
| 顔の向き | 左右・上下・傾き(球に貼った絵を回す考え方で立体的に変形) |
| 目 | まばたき、左右別々の開閉(ウィンク)、笑い目(^^)、視線の移動 |
| 口 | 開閉と、笑顔〜への字。口の差分画像があれば描き分けた口(閉じ・笑顔・「お」・「あ」)に切り替わる。無ければ描き起こしの口 |
| 頬 | 赤み(照れ) |
| 体 | 左右の傾き、回転、呼吸 |
| 髪 | 前髪・前の房・後ろ髪がそれぞれ物理演算で揺れる。長い髪の根元は頭に付いていく |
| 自動の動き | まばたき、呼吸、マウスを目で追う、待機モーション |
| 口パク | マイクや音声ファイルの音量から自動で口を動かす |
| モーション | ライブ2Dと同じ motion3.json 形式をそのまま再生(11本同梱) |
| 書き出し | モーションを連番画像(1枚にまとめた画像)に保存。動画編集やゲームで使える |

## 見てみる

リポジトリの一番上で次を実行し、ブラウザで開きます。

```bash
python3 -m http.server 8765
```

- 確認画面: http://localhost:8765/puppet/demo/ (スライダーで各部を動かす・モーション再生・書き出し)
- 埋め込み例: http://localhost:8765/puppet/demo/embed.html?focus=bust (背景が透明。配信ソフトのブラウザ表示にそのまま使える)

## アプリやページに組み込む

表示エンジンは `runtime/puppet.js` の1ファイルだけで、外部ライブラリは使っていません(WebGLが使える環境なら動きます)。
必要なファイルは `runtime/puppet.js` と、モデルのフォルダ(`puppet.json`・`texture.png`・`motions/`)の2つです。

```html
<canvas id="cv" style="width:400px;height:600px"></canvas>
<script type="module">
  import { PuppetView } from "./runtime/puppet.js";
  const view = await PuppetView.create(document.getElementById("cv"), "./models/kurisu/puppet.json");
  const puppet = view.puppet;

  puppet.playMotion("./models/kurisu/motions/smile.motion3.json");   // モーション再生
  puppet.setParam("ParamCheek", 1);                                   // 値を直接指定(頬を赤く)
  puppet.lookAt(0.5, 0.2);                                            // 右上を見る(-1〜1)
  puppet.setLipSync(0.8);                                             // 口を開ける(数値か関数)
  puppet.connectAudio(document.querySelector("audio"));               // 音声に合わせて口パク
</script>
```

### 主な操作

| 操作 | 内容 |
|---|---|
| `PuppetView.create(キャンバス, モデルのURL, 設定)` | 読み込み・大きさ合わせ・毎フレームの更新・マウス追従をまとめて行う。設定の `focus` に `[x, y, 幅, 高さ]` を渡すとその範囲を拡大表示 |
| `view.setIdleMotions([URL, ...])` | 何も再生していない間に流す待機モーション |
| `puppet.playMotion(URL か motion3.jsonの中身)` | モーション再生。終了時に解決する Promise を返す |
| `puppet.stopMotion()` | 再生中のモーションをフェードアウトして止める |
| `puppet.setParam(名前, 値)` / `getParam(名前)` | パラメータの指定・取得 |
| `puppet.lookAt(x, y)` | 視線と顔の向きの目標(-1〜1) |
| `puppet.setLipSync(値か関数)` | 口パク。`null` で解除 |
| `puppet.connectAudio(音声)` | audio要素・マイクのストリームの音量で口パク |
| `puppet.auto.blink / breath / lookAt / physics` | 自動の動きの入り切り(true / false) |
| `puppet.fit(余白, 範囲)` | 表示位置の合わせ直し |

自前で描画の流れを管理したいときは `Puppet.load(キャンバス, URL)` で読み込み、毎フレーム `puppet.update(経過秒)` と `puppet.render()` を呼びます。

### パラメータ一覧

名前はライブ2Dの標準名に合わせています。そのため、ここ用に作ったモーションは標準的なライブ2Dモデルでもほぼそのまま動き、逆にライブ2D用のモーションもある程度そのまま再生できます。

| 名前 | 意味 | 範囲 |
|---|---|---|
| ParamAngleX / Y / Z | 顔の向き 左右・上下・傾き | -30〜30 |
| ParamEyeLOpen / ParamEyeROpen | 左目・右目の開き(キャラクターから見た左右) | 0〜1 |
| ParamEyeLSmile / ParamEyeRSmile | 笑い目(開きを0にすると ^^ になる) | 0〜1 |
| ParamEyeBallX / Y | 視線 | -1〜1 |
| ParamMouthOpenY | 口の開き | 0〜1 |
| ParamMouthForm | 口の形(1で笑顔、-1でへの字) | -1〜1 |
| ParamCheek | 頬の赤み | 0〜1 |
| ParamBodyAngleX / Z | 体の傾き・回転 | -10〜10 |
| ParamBreath | 呼吸 | 0〜1 |
| ParamHairFront / Side / Back | 前髪・前の房・後ろ髪の揺れ(普段は物理演算が自動で動かす) | -1〜1 |

## 同梱のモーション

微笑み、うなずき、首かしげ、照れ隠し、びっくり、ウィンク、考え中、やれやれ、話す、待機(見回す)、待機(ゆらぐ)

追加・変更は `builder/make_motions.py` を編集して実行します。書き方はリポジトリの `tools/gen_motions.py` と同じです。

```bash
python3 puppet/builder/make_motions.py
```

## 口の差分画像を使う

同じ絵柄で口だけを描き分けた拡大図(閉じ・笑顔・「お」小・「お」大・「あ」など)があると、描き起こしの口の代わりに使えます。
`builder/rig_config.json` の `"口の差分"` に画像の場所と、次の位置を書きます(座標は差分画像ならその画素、全身画像なら元画像の画素)。

| 項目 | 内容 |
|---|---|
| 形 | 形の名前 → 画像ファイル。名前は「閉じ」「笑顔」「お小」「お大」「あ」 |
| 基準 | 他の差分を合わせる基準の画像(ふつうは閉じ口) |
| 差分の鼻先とあご先 / 全身の鼻先とあご先 | 大きさを合わせるための2点 |
| 差分の口の線の中心 / 全身の口の線の中心 | 重ねる位置 |
| 範囲 | 口を切り出す範囲(全身の口の線の中心からの差。元画像の画素) |

仕組み(`builder/mouth_from_images.py`):

1. 差分どうしを、口より上(鼻・耳・横髪)の特徴点で基準の画像に合わせる
2. 鼻先〜あご先の長さで大きさを合わせ、口の線の中心どうしを重ねる
3. 肌の色を全身画像に合わせ、肌との色の差で「口だけ」を切り出す(肌の上で元と同じ見た目になるよう、色を逆算して半透明にする)
4. 拡大表示で粗くならないよう、テクスチャは全身画像の3倍の解像度で持つ

口の開き(0・0.5・1)と形(への字・普通・笑顔)の組み合わせで、次の口を表示します。途中の値では、ほぼ切り替えに近い形で混ざります。

| | 閉じ(0) | 半開き(0.5) | 全開(1) |
|---|---|---|---|
| への字・普通 | 閉じ | お小 | お大 |
| 笑顔 | 笑顔 | あ(少し縮めて) | あ |

パーツ分けPSDには、閉じ口(mouth_close)と「あ」の口(mouth_open)を入れます。Anime2.5DRig は閉じ口と開き口の2枚しか扱えないため、笑顔と「お」の口は自作エンジンでだけ使えます。

## パーツ分けPSDとして書き出し、他の道具で動かす

分けた部品は、パーツ分けPSD(レイヤー付きの画像)としても書き出せます。
レイヤー名は see-through(一枚絵を自動でパーツ分けする研究)の出力と同じにしてあるので、次の道具にそのまま読み込めます。

```bash
python3 puppet/builder/export_psd.py puppet/models/kurisu/kurisu_bust.psd 250,0,830,720   # バストアップ
python3 puppet/builder/export_psd.py puppet/models/kurisu/kurisu_full.psd                  # 全身
```

| 道具 | 内容 |
|---|---|
| [Anime2.5DRig](https://github.com/852wa/Anime2.5DRig) | ブラウザにPSDを入れるだけで、首振り・まばたき・口パク・髪揺れ・カメラでの顔追跡・透過動画の書き出し・配信ソフト連携まで自動。日本語の画面 |
| Live2D Cubism Editor | PSDを読み込み、手作業できちんとリグを組む(いちばん高品質。手間はかかる)。できた moc3 にはこのリポジトリのモーション追加の仕組みがそのまま使える |
| [Stretchy Studio](https://github.com/MangoLion/stretchystudio) | ブラウザで動くリグ作成ツール。腕の骨組みの自動生成など。Spine形式で書き出し |

Anime2.5DRig 用には、髪の層どうしの奥行きの差を小さくした設定ファイル(`kurisu_bust.rig.json` など)も用意してあります。
差が大きいままだと、首を振ったときに前髪と後ろ髪が大きくずれて切れ目が見えるためです。
読み込むには、画面の「設定JSONを読み込む」を押すか、配信用表示のアドレスに `&settings=kurisu_bust.rig.json` を付けます。

### いちばんきれいにしたいとき(see-through)

このフォルダの自動分解は、色の違いと計算で分けているため、髪の束の境目までは正確に分けられません。
[see-through](https://github.com/shitagaki-lab/see-through)(2026年の研究。AIが一枚絵を最大23層に分け、隠れた部分もAIが描き足す)を使うと、はるかにきれいなPSDが得られます。

- 12〜16GBの画面用メモリ(GPU)が必要です。持っていない場合は、HuggingFace のオンライン実演(無料の登録が必要・1日1〜2回・1回2〜3分)で試せます
- 出てきたPSDは Anime2.5DRig にそのまま読み込めます

## 画像から作り直す(別の画像で作るとき)

```bash
pip install numpy opencv-python-headless pillow scipy torch psd-tools   # 初回のみ
python3 puppet/builder/upscale.py 元画像.png 元画像_x2.png 2   # 高解像度化(数分〜10分程度。省略可)
python3 puppet/builder/build_rig.py                            # 部品に分解してリグを作る(1〜2分程度)
python3 puppet/builder/make_motions.py                         # モーションを作る
```

PSD書き出しで使う閉じ目・開き口の画像(`models/kurisu/layers/閉じ目.png`・`開き口.png`)は、表示エンジンで描いて作ります。
`demo/parts.html` をブラウザで開き、「閉じ目と開き口を保存」を押すと保存されます。

- 元画像の場所・目や口の位置・前の房の通り道などは `builder/rig_config.json` に書きます。座標は元画像のピクセル単位です
- 部品の分け方は `models/kurisu/debug/` に画像で出ます(`01_振り分け.png` が色分けした全体図)。うまく分かれていないときは設定の座標を直してください
- 正面を向き、髪と肌・服の色がはっきり違う立ち絵ほどうまくいきます

## 仕組み

1. **高解像度化**(`builder/upscale.py`): ギットハブで公開されているアニメ絵向けの超解像モデル Real-ESRGAN(アニメ用6ブロック版)で2倍に拡大します。ネットワーク構造はこのファイル内で再実装しており、重みは初回に自動でダウンロードします
2. **部品への分解**(`builder/build_rig.py`): 髪は色で見分け、後ろ髪・前の房・前髪に分けます(髪のすぐ外の暗い輪郭線も髪に含める)。顔・白目・瞳・まつ毛・口・体も分けます
3. **隠れていた部分の塗り足し**: 胸の房の下の白衣や、白衣の下の後ろ髪は、ギットハブの IOPaint が配布しているアニメ・漫画向けの塗り足しモデル LaMa(`builder/inpaint_lama.py`)で、しわや襟の線をつなげて描き足します。顔の後ろの髪は、LaMa だと髪の中に顔を描いてしまうため、なめらかな髪の色を縦方向にならして塗ります。前髪の下の肌や目・口の跡は多重解像度の塗り足し、首はあごの少し下の色を上へ延ばします。口の中・下唇・頬の赤みは描き起こしです
4. **リグの生成**: 本家ライブ2Dと同じく「パラメータ → キーフォーム(基準の形)の補間 → 変形器(格子を動かすワープ・回転)の連鎖 → メッシュの頂点」という仕組みで、変形を計算で作ります
5. **表示**(`runtime/puppet.js`): WebGLで描画します。目は「目の形」で切り抜いて描き(ステンシル)、髪揺れはばねの物理演算です

## 限界

- 元が正面の1枚絵なので、顔の向きは左右それぞれ10度前後の「それらしい」回転です。真横や後ろは向けません
- 三面図(横・後ろ)は使っていません。ライブ2D式の動かし方は正面の絵を変形させるもので、横や後ろの絵を混ぜる仕組みがないためです。三面図を生かすなら立体(3D)モデルを作る方法になります(下記)
- 腕・手は体と一体で動きます(手を振るなどは不可)。腕を動かすには、腕を別の絵として描き足す必要があります
- 眉は前髪に隠れて見えないため、眉の動きはありません
- 首振りを大きくすると、首の横や髪の根元に塗り足した部分が見えることがあります

## 三面図を生かしたいとき(立体モデル)

正面・横・後ろの絵があると、AIで立体モデルを作る道具が使えます。立体モデルなら、どの方向にも向けます。

- [Hunyuan3D-2](https://github.com/Tencent-Hunyuan/Hunyuan3D-2) の多視点版(Hunyuan3D-2mv): 正面・左・後ろの画像から立体の形を作る
- [CharacterGen](https://github.com/zjp-shadow/CharacterGen): アニメキャラクターの画像から、手足を広げた姿勢の立体モデルを作る
- できた立体モデルに骨組みを付けて VRM 形式にすれば、VTuber用アプリなどで広く使えます

どれも高性能なGPUと、HuggingFace からの重みのダウンロードが必要です。この作業環境ではどちらも使えないため、試していません。
